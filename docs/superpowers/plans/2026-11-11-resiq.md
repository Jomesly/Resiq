# Resiq Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a deployed web app where users upload receipt photos. The app preprocesses each photo, OCRs it, extracts structured PH-receipt fields with confidence scores, and lets the user review, correct, export, and summarize them.

**Architecture:** Next.js frontend talks to a FastAPI backend. Uploads are stored on disk (Railway volume) and enqueued as rows in Postgres. A worker process claims jobs with `FOR UPDATE SKIP LOCKED`, runs OpenCV preprocessing, then PaddleOCR, then rule-based extraction, and writes the machine `extraction` (JSONB) plus prefilled editable columns. The UI polls status, then shows a split review screen.

**Tech Stack:** Python 3.12, FastAPI, SQLAlchemy 2 (sync, psycopg 3), Alembic, Pydantic v2, OpenCV-headless, Pillow + pillow-heif, PaddleOCR 3.x, rapidfuzz, pytest. Next.js (App Router, TS), Tailwind v4, shadcn/ui, TanStack Query, react-hook-form + zod, Recharts, lucide-react, `next/font` (Besley + Hanken Grotesk + Azeret Mono), Vitest + Testing Library, Playwright + @axe-core/playwright. Postgres 16, Docker, GitHub Actions, Railway, Vercel.

**Spec:** `docs/superpowers/specs/2026-11-11-resiq-design.md` (product) and `docs/superpowers/specs/2026-11-11-resiq-ui-design.md` (UI system, components, screens). The UI is an original "columnar book" direction made with the Hallmark skill, using the user's Monad reference (`docs/design/monad/`) as inspiration only. The visual target is `docs/design/mockups/ledger/index.html` (landing) and `ledger/review.html` (review screen + states). Check every frontend task against them in a browser.

## Global Constraints

- Python `>=3.12`. Node `>=20`. Postgres `16`.
- Money: `Decimal` in Python, `NUMERIC(12,2)` in DB, string in JSON (e.g. `"1250.00"`). Never float.
- Accepted uploads: JPEG, PNG, WebP, HEIC, detected by magic bytes. Max `10 MB` (`413` above, `415` for other types).
- Numeric dates parse as MM/DD/YYYY (PH). Dates in the future or older than 10 years are rejected.
- TIN regex: `\b\d{3}-\d{3}-\d{3}(?:-\d{3,5})?\b`. VAT rate `0.12`.
- Receipt statuses: `queued | processing | needs_review | verified | failed`.
- Confidence display thresholds: `< 0.6` amber "check", `< 0.3` or `null` red.
- Categories (exact): `Food & Drinks, Groceries, Transport, Fuel, Utilities, Office Supplies, Health, Other`.
- Tests never load PaddleOCR. `OCR_ENGINE=fake` in tests/CI/e2e. `OCR_ENGINE=paddle` in prod.
- Every API route except `POST /api/workspaces`, `GET /healthz`, and signed image URLs requires `Authorization: Bearer <token>`, and a workspace may only see its own rows (`404`, not `403`, for other workspaces' IDs).
- **UI (UI spec Sections 2–3, the "columnar book" direction):** every colour and font goes through a token, never raw hex. The canvas is ledger-green `--color-paper`. Headings, legends and the wordmark are Besley 500. All UI text is Hanken Grotesk. Azeret Mono is **only** for receipt-derived figures (amounts, TIN, OR no.). Labels, table heads, chips and nav are sentence case: no uppercase, no tracked capitals, no eyebrows, no mono labels, no middle-dot strings. **Ballpoint blue (`--color-accent`)** marks only the one primary action per screen, the current selection, focus, and any value the user typed. **Closing red** marks only a balanced total's double rule and errors. Radius is 6px everywhere (no pills). No card shadows. Hairlines use `--color-rule`; control borders use `--color-rule-strong`. Status is always words in a tinted chip. Light theme only. Touch targets 44px. `prefers-reduced-motion` stops all animation. Never `transition: all`.

## Review Focus

1. **EXIF-rotated / sideways phone photos.** Pixels must be upright before OCR. Exercised in Task 8 (`test_exif_orientation_applied`) and Task 10 (Paddle doc-orientation classifier enabled).
2. **No document contour found** (receipt fills the frame, or the receipt sits on a white desk). The pipeline must fall back to the unwarped image, not crop to garbage. Task 9 (`test_no_quad_falls_back_to_full_image`, `test_tiny_quad_rejected`).
3. **Amount traps:** `SUBTOTAL`, `TOTAL ITEMS: 3`, `TOTAL QTY`, `P1,25O.00`, `₱ 1 250.00`. The total must be the payable amount, OCR-confusion tolerant. Task 11/13 tests.
4. **Ambiguous / bad dates:** `03/04/2025` → March 4. `04-Mar-25`. A future date or a phone number like `0917-123-4567` must not become a date. Task 11.
5. **Worker crash or OCR exception mid-job.** The receipt must never be stuck in `processing`. The lease expires and the job is reclaimed. After 3 attempts the receipt goes to `failed` with a message. Reprocessing a `verified` receipt requires `force=true`. Task 7 and Task 17.
6. **Review screen at phone width / with a tall receipt.** Overlay boxes must stay aligned with the text when the image scales (SVG `viewBox` = processed-image pixels, not CSS pixels). The form must stay usable under a sticky viewer at 375px. Task 20 (`overlay boxes scale with rendered image`) and Task 23 (screenshot + no-horizontal-scroll check at 375/1024/1440).

### Task 7: Postgres job queue + worker loop

**Files:** Create `backend/app/worker/{queue.py,runner.py}`, `backend/tests/worker/test_queue.py`.

**Interfaces:**
- `claim_next(session, lease_s: int = 300) -> Receipt | None`: one statement:
  ```sql
  UPDATE receipts SET status='processing', attempts=attempts+1,
         lease_expires_at=now() + make_interval(secs => :lease)
  WHERE id = (SELECT id FROM receipts
              WHERE status='queued' OR (status='processing' AND lease_expires_at < now())
              ORDER BY created_at FOR UPDATE SKIP LOCKED LIMIT 1)
  RETURNING *;
  ```
- `complete(session, receipt_id: UUID, **fields) -> None` sets `status='needs_review'`. `fail(session, receipt_id: UUID, error: str, max_attempts: int = 3) -> None` requeues if `attempts < max_attempts`, else `status='failed'`. Both clear `lease_expires_at`.
- `run_worker(process_fn: Callable[[UUID], None], stop: threading.Event, poll_interval_s: float = 1.0) -> None`: claim → `process_fn` → on exception `fail(..., str(exc)[:500])`. SIGTERM sets `stop`. Entry point `python -m app.worker.runner`.

### Task 13: Totals, VAT breakdown, consistency checks

**Files:** Create `backend/app/extraction/totals.py`, `backend/tests/extraction/test_totals.py`.

**Interfaces:**
- `extract_totals(rows) -> dict[str, FieldValue[Decimal]]`, keys `subtotal, vatable_sales, vat_amount, vat_exempt, total`.
- Label patterns (case-insensitive; `total` searched bottom-up, the others top-down; first match wins):
  - total: `\b(GRAND\s+TOTAL|TOTAL\s+AMOUNT(\s+DUE)?|AMOUNT\s+DUE|TOTAL\s+DUE|TOTAL)\b`, skipping rows that match `SUB\s*-?\s*TOTAL|TOTAL\s+(QTY|ITEMS?|SAVINGS|DISCOUNT)|VATABLE`.

- Confidence: a label hit = 0.9 × row conf. Total fallback when no label = the largest amount in the bottom 60% of rows, at 0.4.
